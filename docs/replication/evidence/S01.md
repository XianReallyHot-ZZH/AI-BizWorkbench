## 4. 失败现场（不删不改）

1. **测试 helper 引用错表**：commit 1 版 `learn_run` 从 `evidence` 表取记录，但测试运行库里
   来源任务走 executions、evidence 表为空——`first_evidence_id()` 会拿到 NULL。修复：改按任务从
   `executions` 取（`exec_id`），T-DLV 改走 `run_task` 保证绑定任务有执行记录可引用。
2. **C12 设计错**：自召回断言需要 active 资产，原测试资产停在 candidate 会先被状态过滤掉，
   self_source 分支永远走不到。修复：先经独立具名审核发布，再从来源任务自召回。
3. **C5/C10 篡改面设计错**：原打算篡改 evidence 表，但来源快照引用的是 executions——改双资产
   设计（A 验载荷校验、B 验来源引用链），并做"正文+摘要列"一致性手改（最强篡改形态）。
4. **实现缺陷 ×2（均由测试抓获，test-first 生效）**：
   - `_check_source` 读 `source["execution_refs"]`，实际结构为 `source["snapshot"]["execution_refs"]`
     ——来源引用链复核整体空转（C5/C10 的 source 段以 rc=0 抓获）；
   - 召回包 payload 键 `id` 与合同词面 `recall_id` 不一致（6 例 KeyError 抓获）。
   两处修复后全绿；修复前的失败输出已在工作账红记录 R2 前的中间轮（未单独入链，现场为
   `13 tests: FAILED (failures=1, errors=7)` 一轮，如实记于此）。

   - Spec 轴：C1 种子只做了召回/采用两支，govern 无项目校验、跨项目治理不拒——补 `--project-id`

- 五表对齐上游命名（learning_assets/events/recalls/bindings/runs），DDL 单一来源
  `bootstrap._LEARNING_SCHEMA`，init 与 `_ensure_v0_schema` 旧账迁移共用

- 链 = sha256 快照链：资产/召回包/绑定读取时重算校验；来源引用链比对执行记录摘要列；
  learn-run 不收自报哈希，模块从账本记录现算
- 治理门槛：human() 词面拒 AI/占位名义；非提炼者独立审核；publish 前必须 approve；
  publish 同事务原子 superseded 同 family 旧 active（事件带 replacement）
- memory 类复用失败只记 outcome 不自动撤回（上游口径）；失效全走状态迁移+事件，不删除
