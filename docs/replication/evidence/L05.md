## 6. 口径与限制

- **同命令异树口径（C4，逐字披露）**：红绿两条记录的 `command_text` 为逐字节相同命令串；目标树差异经环境变量 `L05_EVAL_TARGET` 注入（红=缺陷基线，绿=真实候选），由输出内 `pwd` 行、封存 `meta.json` 的 argv 与本账三重披露。链判定的"同命令"语义（同一检查、先红后绿）在"同一检查命令、缺陷树红/正确树绿"上成立——这是本讲增量重定位（D1）的设计本意，非账面技巧。
- **失败信息定位口径（C3，复查轮修正版）**：客户 eval 为裸 `assert`，harness 的 error 载荷仅 `{"type","message"}`（`run_suite` 源码实证），任何输出与报告均**不含断言表达式**（初版口径曾误称含 traceback 行，已在 §4-1 如实纠正）。不能改客户 eval 加消息（改即违 D1"不重写客户检查"）。实际定位三件套 = 用例名 `receiving_is_idempotent`（其名即幂等要求）+ `[BLOCK]` 行与 `decision: block` + 绿腿 evidence 文案（「重复入库键只生效一次」，语义同边界 #2）；具体到库存数值的失败定位由 observing 驱动承载（record 55：`expected on_hand 28 / actual 36` + `requirement: 同一笔收货只入账一次：库存与流水都不得重复` 逐字文本）。上游通过标准「失败信息能够定位到具体要求」以此组合满足，blocking 定位在客户用例名级，observing 数值级，两层均封存在案。
- **驱动身份口径（D4）**：`receiving_scenario_check.py` 是 observing 补充（C6/C7），**不冒充** blocking 身份；blocking 身份恒为客户用例 `receiving_is_idempotent`（冻结指纹内）。
- **执行期技能口径**：本讲执行期经用户显式调用 `/mattpocock-skills:implement` 启动（2026-09-28）；复查轮经 `/mattpocock-skills:code-review master...lesson-05` 双轴并行子代理（同 L04 先例）。tdd 技能未走（见下条）。
- **缺陷基线口径（D2/R2）**：基线仅存在于 `.runtime/course/L05-defect-baseline/`（gitignored，永不合入）；构造可复现（`evals/l05/build_defect_baseline.py`，锚点守卫）。候选分支内产品 diff 为空——客户已实现幂等，本讲不做"实现幂等"的伪交付。
