## 3. 失败现场（一律保留不删）

1. **起始红假绿两用例（commit 1 途中）**——`repairMapRejectsExistingOutput` / `repairMapRequiresObservedExit` 断言恰为 rc 2，与未注册 invalid choice 同码成假绿（首采 160/20）；补 `invalid_report` / `observed-exit` 词面断言后 22/22 全红重采（160/22）。commit 1 信息如实记录。

3. **`Map.of` 缺闭合括号**——CancelChecks 编译失败一次；补括号。
4. **CancelChecks 空选集误拒（真树首跑抓到，先于合同测试）**——未传 `--case` 时 `run.size()=9 != selected.size()=0` 误拒全跑；修过滤校验（非空选集才校验）+ 补 `cancelChecksRejectsUnknownCase` 回归锚。
5. **Args repeating 覆盖语义（真实使用抓到）**——`--case` 重复出现 `put` 覆盖只留末项，首版草案 `required_cases` 缺项；test-first 修（`computeIfAbsent` append，连续多值兼容；L04 `--write-scope` 面零回归经全量 161/161 验证）+ 合同测试补多 `--case` 断言；首版草案留档 `repair-draft.json` 不删，v2 为有效草案。
6. **repair-map 首喂 suite 失配**——报告 suite=all vs 默认 blocking，`invalid_report` 正常拒绝（操作失误非缺陷）；补 `--suite all`。
7. **空输出 diff 被诚实护栏拒收**——恢复后 diff 无差异，`b8d2b12a`（rc 0 空 output）导入被拒（「输出为空，记录未追加」——L01 护栏，语义正确）；留痕不删，机器链改走实现面 git diff（§5 裁量）。

9. **verify workspace_invalid**——候选树缺 `.git`；补 git init + 起点封存 `49b369e`（净态）后 verify 通过。

## 5. 执行期裁量与偏离披露

1. **注入形态自拟（D5 如实记录）**：上游 `assets/latest/candidate-*` 原始 JSON/diff 在 pin 内缺席（只有 html/png 渲染件）——注入行为本讲自拟（锚点唯一性机检在场），与上游「跳过释放分支」教学语义同形。
2. **机器链 diff = 实现面 git diff（混搭披露）**：业务语义的注入/恢复 diff（record 83，rc 1）留账不参与机器链；机器链闭合用 `git diff ec3228f..0a4eb17`（实现面，rc 0）居间——L08 §3.6 工具链补链同构。空输出护栏拒收恢复后 diff（§3.7）是促成因素，护栏语义正确。
3. **修复链人审环节（D6）**：草案四要素（allowed_files=单文件 / objective / scope 四项一因 / reproduce-acceptance）呈报用户具名确认，原话「没问题，继续」（2026-10-01）。
4. **erp_increment「修复」的表达**：移除教学注入（反向替换一行）——客户实现本就正确（讲义 §1.3），注入是教学装置非真实事故；恢复后候选树与 vendors 字节级一致，形态差异如实（L08 先例直承）。
5. **旧草案 v1 留档**：Args bug 态产物（required_cases 缺项）不删，`repair-draft-v2.json` 为经确认的有效草案。
6. **Candidates 树 git 起点**：`.runtime/course/L09-candidate` git init @ `49b369e`（净态封存，verify 前置要求）。
7. **红报告生成运行无独立 capture（复查轮 T-2 披露）**：带 `--report-path` 的生成运行与 03-failure 采的 `--no-report` 运行是同命令两次执行；账本红以 `--no-report` 面为准，报告文件内容经草案 `report_sha256`（`baab1e1c…`）机器锁定，不经人手转述。
