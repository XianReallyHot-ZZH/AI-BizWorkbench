## 3. 失败现场（一律保留，不删不改）

1. **capture 工具误触发**：起草期对 `capture_evidence.py red --help` 误当子命令执行，在封存目录 `lesson-02-submission/03-failure/` 留下 rc 127 无效记录 `20261002T142430314909Z-3530fcc9`——判定为误触发垃圾非证据（rc 127 = 命令不存在，非检查失败）且污染 L02 已封存目录，已删除该目录并在此如实披露（铁律 3 精神：失败记录指真实检查失败的证据链，误操作残留的处置透明）。
2. **SQLITE_BUSY 同进程互锁**（L15Checks governed 分支开发期）：EvolutionStore.verify 的 BEGIN IMMEDIATE 事务内构造 LearningStore → 建表连接与事务写锁互锁（`[SQLITE_BUSY] The database file is locked`）——修复：governed 只读检查移事务前（状态闸门仍在事务内复核），形态差异落账 javadoc。
3. **ResultSet 关闭后读取**（EvolutionStore.get 开发期）：row() 的 try-with-resources 关闭 ResultSet 后 get() 再经 connRow 读取 → SQLException——修复：get() 自查自读，EvolutionRow 去掉 ResultSet 承载。
4. **JsonNode 越过 PyJson 输出边界**（开发期）：decode 把 parse() 的 ArrayNode 直接放入输出 Map → PyJson「不可序列化的类型」——修复：toJson 助手（convertValue）在输出边界统一转换；LearningStore 的 decisions 同款修正。
5. **五拍实验拍 4 首跑失败**：`workbench-learn-bind --actor Claude` 被 human() 门拒（`human_actor_required: 操作人必须具名人工：'Claude'`）——**不是缺陷是合同实证**：S01 HUMAN_FORBIDDEN 增补 claude 在真实链路生效（AI 名义不得做采用决定）。失败件保留为 `09a-learn-bind-rejected-ai-actor.txt`；修正采用决定人 = 用户具名重走（09b）。
