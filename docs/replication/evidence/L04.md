## 6. 口径与限制

- **责任口径（C6 措辞，逐字）**：调用正常结束 ≠ 业务正确；退出码 0 ≠ 客户结果正确。
- **C8 版本锚定口径**：复核记录经 `execution_id` 锚定该次执行的 diff 摘要与 change_manifest——接受对应对具体版本的机器可查事实；账本外对 workbench 源码的改动不由任务账检测，由候选分支 git 证据与本账流程兜底（讲义 §4 A 段清单项）。
- **替身执行器证明边界（D7）**：合同测试证明 V0 机制（写集正反、记录保真、状态门、自验拒绝、前置绑定），不证明真实 `claude -p` 行为；后者由 Ticket B 受控执行实跑留证。
- 写集检查的如实限制：事前约束 = 候选工作区绑定 + argv 注入提示词；事后 = 候选 git 状态实测比对。提示词约定不构成事前全部防住（上游同口径：停止推进 ≠ 自动还原）。
- `_collect_changes` 执行 `git add -N .`（意图添加）：改写候选 git 索引以使未跟踪文件进入 Diff——不改文件内容，候选为 scratch 副本；eval 与复验所见工作树内容不受影响。
- 自批拒绝为**名义级比较**（复核人 vs 最近执行者的自报具名字符串）：单人仓库内唯一真人具名验收人（用户）是该门的最终权威；别名绕过属人为造假，由具名验收与红旗清单兜底。
- 摘要口径双轨如实声明：stdout/stderr/diff/eval_output 四段摘要对账本内**存储文本**（保护账本不被手改）；change_manifest 前后值对**文件原始字节**（保护交付物指纹）。
- eval.harness 待建设（L05+）；`inventory_export_is_stable` 将以 probe 实跑承载（D2，B 段）。
- `acceptance: pending_human_review` 恒待人签；**待审核 ≠ 已接受**。
