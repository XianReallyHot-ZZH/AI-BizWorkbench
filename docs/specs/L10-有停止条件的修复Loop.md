## Problem Statement

L09 之后，我能把一份红灯报告确定性地翻译成修复任务草案，并走通一轮人确认范围的受控修复。但那是一条**人驱动的单轮链**：第一次修改后检查没全过时，要不要再来一轮、由谁依据什么决定继续还是停、停的时候接手者能知道什么——全部没有承载。重复说「继续修」不会证明进展：同样的失败可能反复出现、修复可能在两条规则之间来回摇摆、末轮修改可能永远等不到后置检查、Token 与时间在无人核算中耗尽。上游参考实现给出了循环骨架但明示留了四个缺口：执行器异常直接裸抛没有结构化结果、空报告被误判为收敛、末轮待复验没有显式标记、检查面没有独立超时。同时，本讲的业务交付（已预占订单合法发货、非法状态迁移阻断）在客户侧只有 draft 跳转一项默认检查：合法发货的库存与流水断言、cancelled/重复发货的拒绝后不变、其他订单保护、以及「全部拒绝」这种错误修复的辨识，都没有裁判。

## Solution

工作台新增 **Loop 控制器**：一轮 = 一次检查决策轮（检查当前候选 → 有阻断失败且仍允许继续才生成修复任务 → 调用执行器修改 → 修改后的候选在下一轮开头接受检查），按固定顺序决策——报告有效性 → 达标即停 → 预算（轮数/时间/Token，三轨不可互换）→ 进展（失败签名相邻相同即停）→ 授权范围。五类核心停止条件（达标即停、轮数到限、无进展、时间到限、Token 到限）加安全停止路径（执行器异常/报告无效/缺可核验用量），每种停止留下可接续的 History：当前候选与最后已验证候选分开保存，末轮修改后的剩余失败标注来源轮次与待复验。**补齐上游四个缺口**是本讲建设核心：执行器异常结构化停止、报告有效性先行（空报告拒绝不误判收敛）、两候选分开 + 待复验显式标记、检查子进程独立超时。每轮任务复用 L09 严格映射器（不重蹈上游 legacy 洞）。配套建设发货面探针与统一入口登记项（五模式断言留 Java、客户绑定 eval 原名照跑、冻结指纹复核），再以受控候选实验留下**两条真实轨迹**：一次收敛（注入 → 检查红 → 任务 → 预设补丁恢复 → 检查绿 → converged）与一次未收敛（执行器空转 → stopped_no_progress，候选未变如实），外加 last-repair 形态（末轮修改待复验 + 循环外审计单独保存）作第三条对照——控制器建成即被真实使用，收敛与停止两种结束都诚实可查。

## User Stories

1. 作为具名验收人，我想要控制器把「修改—检查—决定下一步」按固定顺序重复执行且最多三轮，以便自动修复不会无限投入，也不会为凑轮数多改。
2. 作为具名验收人，我想要一轮的计数口径钉死为一次检查决策轮（修改发生在两次检查之间），以便「三轮」的含义可从 History 重建而不是靠口头解释。
3. 作为具名验收人，我想要达标即停——有效报告无阻断失败立即返回 converged 不再调用执行器，以便已通过的候选不被继续扩大改动。
4. 作为具名验收人，我想要无进展检测以失败签名（阻断失败名排序）相邻相同为停止依据，以便同签名重复时停止消耗交回调查，且我知道这是保守近似（同名原因变化、A/B/A 振荡不保证被它抓住——能力边界如实声明）。
5. 作为具名验收人，我想要轮数、时间、Token 三种预算分轨且互不替代，以便轮数管次数、时间管历时、Token 管模型用量各守各的边界。
6. 作为具名验收人，我想要 Token 预算按软边界语义记账——单次用量超过剩余额度时累计实际值、剩余归零、停止下一次调用，但绝不宣称「从未超预算」，以便超额事实与停止策略分开呈现。
7. 作为具名验收人，我想要执行器未返回正用量时停止核算并显式返回缺用量状态，以便「没有用量数据」永不被当成免费运行。
8. 作为具名验收人，我想要执行器异常（含超时）被捕获为结构化停止结果并保存已启动事实、最后报告、Diff 与待复验项，以便异常后的现场可查（上游裸抛缺口的补齐）。
9. 作为具名验收人，我想要报告有效性先于达标判定——空结果或协议无效的报告被拒绝进入决策，不再被误判为 converged，以便上游 empty-report 接口反例在本仓库不可复现。
10. 作为具名验收人，我想要 loop-result 把当前候选与最后已验证候选分开记录、末轮修改后的剩余失败标注来源轮次与待复验标记，以便接手者永远知道「最后检查的是哪版、最新代码是哪版」（上游末轮缺口的补齐）。
11. 作为具名验收人，我想要每次运行使用独立运行目录、旧证据永不覆盖，以便三条轨迹的原始材料互不污染、可分别下钻。
12. 作为具名验收人，我想要循环外审计单独保存且不计入 Loop 轮次，以便「循环后来通过」永不回填为「循环内收敛」。
13. 作为具名验收人，我想要合法发货的裁判覆盖库存三量（在库/总预占/可用 = 6/2/4）、其他订单不变、恰好一条双 -4 的 ship 流水，以便只改状态标签证明不了的两笔变化被真实检验。
14. 作为具名验收人，我想要 draft/cancelled/重复发货三条拒绝路径各有登记项且断言拒绝后四张表不变，以便「非法迁移被阻断且订单状态不变」（合同验收断言）有失败路径证据。
15. 作为具名验收人，我想要「全部拒绝」这种错误修复可被识别（合法路径检查红而非法路径绿），以便挡住非法跳转但破坏合法业务的候选无法蒙混过关。
16. 作为具名验收人，我想要客户绑定 eval 以客户原名照跑（客户真理，ADR-0005），以便本仓库绿灯不冒充客户业务结论。
17. 作为具名验收人，我想要默认执行态为 dry-run（只生成修复任务零执行）、真实修改需显式授权，以便一次意外的 `loop-run` 不会改动任何候选。
18. 作为执行者（Claude），我想要控制器库核以三个函数接口（检查/执行/时钟）注入依赖，以便十二种控制模式用合成输入机检决策序与停止状态，与上游 loop_control_lab 同形。
19. 作为执行者，我想要 CLI 面与库核同一实现且经 REGISTRY 注册（loop-run），以便行为类测试经公开子进程接口覆盖参数校验、退出码（converged 为 0，其余为 2）与落盘行为。
20. 作为执行者，我想要每轮生成的修复任务复用 L09 严格映射器（三态、来源哈希、human_review 恒 pending），以便 Loop 不重蹈上游 legacy 映射器的洞，且每轮委托与 L09 链同构可对账。
21. 作为执行者，我想要注入装置在拷贝树上以上游逐字锚点行复刻「拒绝一切发货」的教学缺陷（锚点唯一性机检、幂等护栏、永不写回 vendors），以便受控候选实验有真实 Diff 且不伪称客户事故。
22. 作为执行者，我想要预设补丁执行器如实标注替身身份与合成用量，以便教学轨迹永不冒充真实模型修复（上游明示口径）。
23. 作为复验者，我想要十二种控制模式（含已补齐的 executor-error 与 empty-report 行为）全数机检且计数与上游表格逐项对齐，以便控制器决策面的每个分支有合同证据。
24. 作为复验者，我想要 stopped 状态、业务通过、负责人接受三层结论分别留证，以便「预算耗尽被记录为未收敛而非成功」（合同验收断言）可亲手核对。
25. 作为复验者，我想要客户 eval 双树指纹与发货面客户源件指纹初冻并收口复核，以便检查冻结不被偷偷改动。
26. 作为其他订单（OTHER，业务视角），我想要 TARGET 发货后我的预占与订单状态不被触碰，以便别人的发货不破坏我的占用。
27. 作为目标订单（TARGET，业务视角），我想要只有 reserved 状态的我能发货、draft/cancelled/shipped 的我再发被拒绝，以便订单只按状态机迁移（FlowERP 边界 3）。

## Implementation Decisions

- **控制器落点**：新子包 `workbench/loop/`（`repair/` 先例——上游 agent 家族逐件独立建包，loop 是第二件）；纯核决策序 + 可注入缝 + REGISTRY `loop-run` 命令（quality-gate / ci-evidence / repair-map 先例：workbenchIncrement 即工作台能力）。
- **决策顺序**（固定，逐句对齐上游 `agent/loop.py` 并在其前插入有效性步）：报告有效性 → 达标即停（converged）→ 无进展（相邻失败签名相同 → stopped_no_progress）→ 时间预算（轮前检查 → stopped_time_budget）→ Token 预算（已用量达限 → stopped_token_budget）→ 生成修复任务（复用 L09 RepairMapper 严格版）→ 执行器调用 → 用量核算（缺正用量 → stopped_token_usage_unavailable；超支 → stopped_token_budget 软边界）→ 下一轮；轮尽 → stopped_max_rounds（剩余失败来自最后有效报告 + 待复验标记）。
- **参数面**：`--max-rounds`（默认 3，校验 1..10）、`--token-budget`（默认 30000，>0）、`--timeout` 秒（默认 900，>0）对齐上游 CLI；另加 `--suite-command`（检查命令，绝对路径子进程）、`--executor dry-run|patch|claude`（默认 dry-run）、`--runtime-dir`（每运行新目录——上游参考 CLI 缺此参数是其已知局限，本仓库实现并验证）。
- **检查面**：每轮经子进程跑统一入口（ShipChecks --target 拷贝树），schema 1.0 报告 JSON 解析提取阻断失败；检查子进程带独立超时（上游缺口④补齐）。
- **上游四缺口补齐**（本讲建设核心，D4 全补已裁决）：①执行器异常捕获 → stopped_executor_error 结构化结果；②报告有效性先行（复用 L06 ReportContract 校验面，空 results 拒绝）；③loop-result 两候选分开 + remaining_failures 来源轮次标注 + 待复验标记；④检查子进程独立超时。与上游参考实现的差异逐条如实记录。
- **执行器三态**：dry-run 只生成任务；patch = 预设补丁子进程（教学，usage_is_synthetic 标注）；claude = 接线 L04 execution/ProcessRunner 无头面（ADR-0002），本讲接线完成但不强制真实调用。
- **探针与登记项**：ShipProbe 五模式（legal/draft-ship/cancelled-ship/double-ship/refuse-all）子进程 python 驱动客户入门 ERPService（临时库、四表快照、回报不判对错，断言留 Java）；ShipChecks 独立 main 挂 EvalHarness，六件全 blocking：四发货拍 + 客户 `illegal_transition_is_blocked` 原名 + 冻结指纹复核；refuse-all 不进默认门（必红项先例）；控制器十二模式机检落合同测试不进 ShipChecks（上游同分工：业务面 / 控制器面分开）。
- **注入**：锚点 = 客户 service.py ship_order 状态守卫行，上游逐字源在场（candidate_loop_lab.py GOOD/BAD 行逐字，含注释措辞）；BAD 形态 = 拒绝一切发货（合法拍红、非法拍绿——与 L09 跳过释放形态相反，隔离护栏互证）。
- **三轨迹与 CI**：repair / no-change / last-repair 各新运行目录，after-loop-audit 循环外单独保存；本讲不动 L08 CI 工作流（CI_GATE_SPEC 合同写集映射件，跨讲改动留检查点）。
- **退出码**：loop-run converged 为 0，其余停止状态为 2（对齐上游 main）。

## Testing Decisions

- **好测试只测外部行为**：经公开接口（CLI 子进程 / 库核注入缝）断言可观察输出（状态名、轮次计数、执行次数、用量账、落盘 JSON 结构），不测内部私有方法；探针回报原始观察，预期值 Java 侧独立计算不抄返回值。
- **起始红三面**：LoopRunner 缺席 / loop-run 未注册 / ShipChecks main 缺席，经 testsupport/Cli 真实子进程断言（Java 编译不绑实现类，L06-java 教训）。
- **十二模式机检**：库核三注入缝喂合成报告 + 替身执行器 + 可注入时钟（time-budget 不真等），计数与状态对上游表格逐项断言；executor-error / empty-report 两模式断言 D4 补齐后行为（结构化停止 / 拒绝）。
- **先例**：L09 CancelChecks/CancemProbe 六模式与 mapper_boundaries 六断言（业务面收口形态）、L07/L08 冻结指纹复核、golden 六重放不涉本讲（无 Python 先例，验收门替代 = 合同测试 + 三轨迹 + 指纹冻结 + 全量 mvn test，讲义 D9）。
- **受控候选实验**：净树建指纹 + git 起点封存 → 注入（diff 落账 rc 0）→ ShipChecks 红 capture（红点构成如实）→ 三轨迹各新运行目录 → 循环外审计单独保存。

## 勘误（2026-10-02 复查轮后，实现与 spec 分歧钉死）

- **注入缝形态**（User Stories 18 / Testing Decisions「库核三函数接口」）：实现将 SuiteRunner/LoopExecutor/Clock 三缝收敛为 CLI 参数注入（`--suite-command`/`--patch-command` 脚本 + 真时钟真等待），十二模式全经 `loop-run` CLI 子进程承载——高于 spec 字面的进程内接口缝，同语义且不绕公开入口（测试类头注已声明）。spec 原文保留不改，以本勘误为准。
- **退出码面**（Implementation Decisions「退出码：converged 0，其余 2」）：另有 rc 1 = 运行护栏（runtime-dir 已存在拒绝，旧证据不可抹）与基础设施异常；用法错误 rc 2。
- **oscillating 形态**（Testing Decisions 沿上游表格）：上游 lab 单用例报告形态与本仓「检查集集合相等」严格校验冲突，按双用例固定检查集、失败项 A/B 摆动测（3/3 到限不变——检查内容改变后失败数不可比正是上游口径；证据账 §3.1）。
- **决策序**（Solution 段「预算→进展」与 Implementation Decisions「无进展→时间→Token」内部不一致）：以 Implementation Decisions 与上游 loop.py 为准——报告有效性 → 达标 → **无进展 → 时间 → Token** → 任务 → 执行。
- **D4-④ 证据**：检查子进程独立超时经 `WORKBENCH_LOOP_SUITE_TIMEOUT` 环境变量测试缝压短实测（缺省 300s 不变）；该用例并抓获超时路径 `Map.of` 空值 NPE 真缺陷（已修）。
