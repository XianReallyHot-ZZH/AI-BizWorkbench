## Problem Statement

L10 之后，我能把一项交付放进有停止条件的修复 Loop 里纵向重复；但交付一件事常常同时需要几项**互相独立**的工作——补测试与查风险可以同时做，改接口与按旧接口写测试不能。目前我没有任何机械手段回答「这两项任务能否同时做」：靠感觉并行，可能让一个子任务改掉另一个子任务的判断依据（写集/读集重叠），或两个子任务悄悄共用同一份数据库/报告路径互相覆盖；靠一律串行，又把独立工作的等待时间白白叠起来。上游参考件 `agent/schedule.py` 给出了声明检查器（读集/写集/资源集/输入版本 + 重叠判定），但它是纯 Python 库件（无 CLI、无 Java 对应物），且它自己声明了边界：只查申报路径，不扫描真实行为、不锁文件——漏报读取照样返回 allowed（`undeclared-read` 教学反例）。同时，本讲的业务交付（采购申请）在客户侧只有字段面一项默认检查：申请不增加库存的独立断言、五种非法输入拒绝后五表不变、重复编号的当前语义（IntegrityError ≠ 幂等成功）都没有裁判；「局部绿灯与业务失败可同时成立」（同版不同覆盖）的整合判断也没有一次真实走通。

## Solution

工作台新增**声明检查器 Java 对应物**（`workbench/schedule/` 纯核：Subtask 四字段声明 + 路径规范化 + 三交集判定——`W甲∩W乙`、`W甲∩R乙`、`W乙∩R甲` 须空而读读共享允许，含目录覆盖、路径别名、资源交集、输入版本统一、无效路径与重复名拒绝）。配套建设采购面探针与统一入口登记项（七模式断言留 Java、客户绑定 eval 原名照跑、`write_sets_reject_conflict` 直测本核、冻结指纹复核）。再以两层实验把「局部通过 ≠ 整合通过」钉进证据链：**受控同版整合实验**（净态拷贝树 → 以上游逐字锚点注入「申请后提前入库」教学缺陷 → 三次检查 rc 0/1/0——原字段检查绿、六独立拍中仅 normal 拍红（库存 17/2/15）、恢复后七项全绿 → 指纹断言 + diff 互逆）与**真实并行子任务**（两份子任务合同先行 → 声明检查含一次故意冲突被拒留痕 → Claude Code Agent tool 双子代理并行——甲补测试驱动客户真身、乙只读审查采购面 → 活动时间重叠留痕 + 原始产物回收 → 主会话溯源三分类 → 串行整合 → 同版复验）——大纲合同演示结果「测试补全与风险审查并行执行，由主 Agent 汇总结论」由后者真实承载，顺序实验永不冒充原生并行。声明通过 ≠ 执行安全（undeclared-read allowed 照报 but 判断面标注 False independence）；写集落实靠合同 + 事后 Diff 回查（上游明示「提示词只读 ≠ 权限只读」）；并行提效未实测不声称。

## User Stories

1. 作为具名验收人，我想要一个机械的声明检查器回答「这两项子任务能否并行」，以便分工判断不靠感觉、每次裁决可复现可对账。
2. 作为具名验收人，我想要独立性判定覆盖三个交集（甲写×乙写、甲写×乙读、乙写×甲读），以便互相覆盖输出与互改依据的安排都被拒绝，而读读共享同一固定文件不被误拒。
3. 作为具名验收人，我想要目录覆盖被识别（写 `flowerp/` 即与读 `flowerp/service.py` 冲突），以便「我没写那个文件」不能掩盖实际覆盖。
4. 作为具名验收人，我想要路径别名被识别（反斜杠、大小写折叠、`./` 前缀），以便路径写法变化不能隐藏同一目标。
5. 作为具名验收人，我想要越界路径被拒绝（绝对路径、`..` 跳转、通配符），以便声明只接受明确的仓库相对文件或目录。
6. 作为具名验收人，我想要子任务名非空且唯一、共享资源名非空无空白，以便身份与资源无法被混淆。
7. 作为具名验收人，我想要并行子任务输入版本不统一时被拒绝，以便两份结论不会各自基于不同的共同输入。
8. 作为具名验收人，我想要 resource_set 交集被报告为 `resource:` 前缀冲突，以便共用数据库/端口/报告路径这类文件外共享不漏判。
9. 作为具名验收人，我想要 `undeclared-read` 场景如实暴露声明检查器的边界（allowed + False independence 判断面），以便「声明通过」永不冒充「执行安全」。
10. 作为具名验收人，我想要正常采购申请保存五字段（稳定身份 PR-TARGET、规范化 SKU、去空白理由、数量 7、proposed 状态）且可按编号再查，以便「采购申请保存 SKU、数量、原因和稳定身份」（合同验收断言）有正面证据。
11. 作为具名验收人，我想要申请后库存三量仍为 10/2/8、库存流水与其他单据不变，以便「申请 ≠ 收货」的业务边界被独立断言（不是只看申请表多了一行）。
12. 作为具名验收人，我想要零数量/负数量/空白原因/未知 SKU/重复编号五拍各有裁判且断言**拒绝后五表不变**，以便「非法数量不产生采购申请」（合同验收断言）覆盖部分写入风险（只查抛异常不够）。
13. 作为具名验收人，我想要重复编号的当前语义如实呈现为 IntegrityError 而非幂等成功，以便稳定身份不被自动解释成幂等语义（上游钉死口径）。
14. 作为具名验收人，我想要客户绑定 eval `purchase_request_preserves_reason` 以客户原名照跑（客户真理，ADR-0005），以便本仓库绿灯不冒充客户业务结论。
15. 作为具名验收人，我想要 `write_sets_reject_conflict` 以同名登记项直测本讲 Java 核（四组断言对齐上游 eval 口径），以便「写集冲突的子任务不得并行」（合同验收断言）进了默认门而不只是测试。
16. 作为具名验收人，我想要受控同版整合实验留下「原检查绿 + 六独立拍中仅 normal 拍红 + 恢复后七项绿」的三次检查证据（rc 0/1/0），以便「同版不同覆盖可同时成立」有可回查的原始记录而不是一句结论。
17. 作为具名验收人，我想要三次检查的服务指纹断言（前两同第三异、检查指纹三同）+ 注入/恢复 diff 互逆，以便「修复改的是实现不是检查」可机器对账。
18. 作为具名验收人，我想要真实并行以两份子任务合同先行（共同输入固定版本、各自读集/写集/输出/验收/停止条件），以便子代理拿到的边界与事后回查的依据是同一份。
19. 作为具名验收人，我想要并行前声明检查留下一次故意冲突被拒的记录与修订安排，以便拒绝路径不只在测试里走过（上游 SUBMISSION 第 5 项）。
20. 作为具名验收人，我想要两个子代理的活动时间重叠与各自原始产物（甲：测试文件+命令+结果；乙：风险清单含位置/触发条件/依据）留痕，以便「真实并行」可证明而不是主摘要自述。
21. 作为具名验收人，我想要主会话逐条溯源子任务结论并三分类（已证实/待验证/需求未定），以便汇总不是拼接摘要、每条结论可回到原始输出和文件依据。
22. 作为具名验收人，我想要最终接受绑定整合版本（甲产物 unittest 子进程跑 + 统一入口全套绿），以便旧版局部绿灯永不替最终候选作证。
23. 作为具名验收人，我想要子任务写集越界靠事后 Diff 回查（出现合同外改动即红旗），以便「提示词只读」不等于「权限只读」的上游教学点在本仓库有落实面。
24. 作为具名验收人，我想要顺序复验实验与真实并行分层留证（受控实验永不标注为原生并行），以便两类证据不互冒充。
25. 作为具名验收人，我想要并行提效在未做单 Agent 对照实测时明确不声称，以便挑战任务边界（上游钉死）不越界。
26. 作为执行者（Claude），我想要采购面探针以子进程 python 驱动客户入门 ERPService（临时库、五表快照、回报原始观察不判对错），以便断言全留 Java 且客户真身不被进程内 import 污染（L05+ 结构翻译点承袭）。
27. 作为执行者，我想要库存三量走 `service.product()` 计算列断言（available 不在 stock 表），以便探针数据面与客户实现同源（L10 教训④ 承袭）。
28. 作为执行者，我想要统一入口独立 main（九登记项全 blocking、`--case` 选跑、`--target/--python/--report-path` 先例参数面），以便本地与受控实验同命令红绿链。
29. 作为执行者，我想要注入装置以上游逐字锚点行替换（marker 唯一性机检 + 幂等护栏 + 永不写回 vendors），以便教学缺陷有真实 Diff 且不伪称客户事故。
30. 作为执行者，我想要 premature-stock 以探针模式在场但不进默认门（`--case` 选跑承载），以便「检查发现注入缺陷」是护栏不是把门卡死的污染（L09 leak / L10 refuse-all 先例）。
31. 作为复验者，我想要十模式与三交集全数机检且 observed 对照上游 EXPECTED 表（仅 independent/read-only/undeclared-read 为 allowed），以便声明检查器每个分支有合同证据。
32. 作为复验者，我想要客户 eval 双树 + 采购面客户源件 + 本讲 Java 源件指纹初冻与收口复核，以便检查冻结不被偷偷改动。
33. 作为复验者，我想要 V1 失败报告留史不删（恢复后 V2 绿不回填 V1），以便「修复前的失败」永远可回查（铁律 3）。
34. 作为既有申请（PR-OTHER，业务视角），我想要 PR-TARGET 创建前后我的记录与状态不变，以便别人的申请不触碰我的意图。
35. 作为既有订单（OTHER，业务视角），我想要采购申请永不改变我的预占与状态，以便「申请不收货」的边界对既有业务同样成立。

## Implementation Decisions

- **schedule 落点**：新子包 `workbench/schedule/`（`repair/`/`loop/` 先例——上游 agent 家族逐件独立建包，schedule 是第三件）；纯核 = Subtask 声明（name/write_set/read_set/resource_set/input_version）+ 路径规范化（反斜杠转斜杠、casefold 保守比较、`rstrip("/")`、拒绝绝对路径/`..`/通配符 `:*?[]`）+ 重叠判定（相等/根 `.`/前缀包含）+ 资源规范化（非空无空白 casefold）+ `conflictPairs`（写×写、写×读双向、resource 交集 `resource:` 前缀、共享项取更深路径）+ `assertParallelSafe`（input_version 统一 + 冲突拒绝词面 + 结果 dict 含 `parallel/tasks/conflicts/input_version`）；**不进 REGISTRY**（上游 schedule.py 无 main——loop.py/graph.py 均有，唯它没有；调用面 = 统一入口登记项 + 合同测试，如实不造上游没有的命令面）。
- **探针与登记项**：`workbench.evals.l11.PurchaseProbe` 七模式（normal/zero/negative/blank-reason/unknown-sku/duplicate-id/premature-stock；夹具 = A 商品 + 入库 10 + OTHER 预占 2 + PR-OTHER 既有申请；五表快照 before/after；三量走 `service.product()` 计算列）；`PurchaseChecks` 独立 main 挂 EvalHarness 九件全 blocking：`l11_purchase_normal`、五拒绝拍（`l11_purchase_zero`/`_negative`/`_blank_reason`/`_unknown_sku`/`_duplicate_id`）、客户 `purchase_request_preserves_reason` 原名照跑（子进程 python 驱动客户 eval 真身，L09/L10 同族）、`write_sets_reject_conflict`（直测本核，四组断言对齐上游 cases.py:141）、`l11_frozen_checks`（客户 eval 双树 + `flowerp/service.py` + 本讲 Java 源件指纹）；premature-stock 不进默认门（必红项 `--case` 选跑）。
- **注入**：锚点 = `propose_purchase` 内 marker 行 `        return self.purchase(pid)`（方法段内唯一性机检），注入行 = `        self.receive_stock(sku, quantity, "teaching-premature-" + pid)`——两行均上游逐字源（`integration_lab.py:87-88`）；只写拷贝树，永不写回 vendors（铁律 1）；幂等护栏（已注入拒绝重注）。
- **受控同版整合实验**：`.runtime/course/L11-candidate/` 拷贝树（净态建树指纹 + git 起点封存——L09 教训③）→ 注入 diff 落账 rc 0 → 三次检查全经统一入口 `PurchaseChecks --target`（01 客户名原样子集 / 02 六拍 / 03 全套默认门）→ 指纹断言（三次 service_sha256 前两同第三异；checks_sha256 三同）+ 状态快照（before/after/exception）+ restored.diff 与 injected.diff 互逆；每次重跑新目录（`open("x")` 同语义）。红点构成如实入账：过度副作用形态——业务面红点仅 `l11_purchase_normal`（字段绿、库存红 17/2/15），五拒绝拍与客户 eval 绿（隔离护栏恰与注入形态互证，与 L10 过度拒绝形态相反）。
- **真实并行子任务**（D6 核心）：净态拷贝树上两份合同 → Java 核声明检查（先故意提交冲突形态：甲读 `service.py` + 乙写 `service.py` → rejected 留痕；修订乙为只读后通过）→ Claude Code Agent tool 双子代理并行委派（甲 = 补测试：只写拷贝树 `tests/test_l11_purchase.py`，Python unittest 驱动拷贝树客户真身，含库存不变断言；乙 = 只读审查：采购面风险清单，零代码写入）→ 活动时间重叠留痕 + 原始产物回收 → 主会话溯源三分类 → 串行整合 → 同版复验（子进程 `python -X utf8 -m unittest tests.test_l11_purchase -v`，cwd = 拷贝树 + `PurchaseChecks` 全套 rc 0）；写集落实 = prompt 合同 + 事后 Diff 回查。
- **与上游 AST 抽取机制的差异**：上游 integration_lab 以 AST 从客户 eval 源码抽取原检查段拼装临时检查文件；Java 侧登记项即正式检查（无需抽段）——三次检查语义等价（原检查 = 客户名原样照跑子集），差异如实记录。
- **命名**：分支 `lesson-11`；证据账 `docs/replication/evidence/L11.md`；任务 `CASE-WB-L11-001` @ `.runtime/course/L01-workbench-java/`；采集根 `lesson-11-submission/`。
- **CI**：本讲不动 L08 工作流（CI_GATE_SPEC 合同写集映射件；远程复验缺口如实声明，本地全量门承载）。

## Testing Decisions

- **好测试只测外部行为**：经公开接缝断言可观察输出（登记项结果、报告 JSON、observed/allowed 判定、退出码、落盘 diff），不测私有方法；探针回报原始观察，预期值 Java 侧独立计算不抄返回值。
- **起始红三面**：schedule 核缺席 / PurchaseChecks main 缺席 / 探针缺席，经 testsupport/Cli 真实子进程断言（Java 编译不绑实现类，L06-java 教训承袭）。
- **十模式机检**：上游 SCENARIOS/EXPECTED 表驱动翻译，`observed` 逐项对照（仅 independent/read-only/undeclared-read 为 allowed）+ undeclared-read 附加 judgment 面（False independence）。
- **三交集机检**：目录覆盖、路径别名三形态（反斜杠/大小写/`./` 前缀）、无效路径四形态（绝对路径/`..`/通配符/空白）、重复名、资源交集、input_version 不统一、只读共享 `parallel:true`——库核公开方法直调缝承载。
- **先例**：L09/L10 Checks+Probe 合同测试（业务面收口形态与 `--case` 选跑）、L07+ 冻结指纹复核、L10 注入装置 diff 断言；golden 六重放不涉本讲（无 Python 先例，验收门替代 = 合同测试 + 受控实验 + 真实并行留痕 + 指纹冻结 + 全量 mvn test，讲义 D9）。
- **受控实验**：净树建指纹 + git 起点封存 → 注入 → 三次检查（0/1/0）→ 指纹断言 + diff 互逆 → 恢复；每步 rc 落账，失败保留不删。
