## 1. 讲解

### 1.1 本讲要什么

L13 把交付封装成 Task 资源、L14 立起投影面板、L15 收拢反馈→记忆→演进闭环；L16 把整个工作台放进「陌生环境 + 陌生需求」下终验：**系统能否从干净环境按文档启动（冷启动）**、**随机需求能否走完 Spec—实现—Eval—人审—发布证据全链（现场抽取）**、**交付结果能否被没跟过过程的人追溯（发布索引）**。三个增量面：①**ReleaseIndex 发布证据索引**（真新面——验收 3 直接承载：汇集五要素引用 + 列缺项，不代行人审）；②**冷启动**（自检件 + 干净环境受控实验 + 记忆迁移——L15 因果交接兑现：现场新需求 learn-recall 带引用上下文，蓝图 L13-L16 段「反馈与经验复用」收口）；③**现场抽取协议**（liveRequest=true 首见——流程面与证据面：抽取时点/具名/候选池/基线未实现核验，不是预写代码面）。

上游钉死的判断，本讲全链贯穿：**发布索引只汇集引用不构成接受**（`requires_human_review` 恒定 + limitations 三条词面——汇集证据与批准交付是两件事，铁律 2 的发布面）；**证据文件必须在运行目录内且后缀在白名单**（引用越界即拒——证据的可寻址性是追溯的前提）；**Spec 冻结后变更即 gap**（spec_changed_after_freeze——冻结 sha 与现算 sha 对照）；**执行者不得自签**（reviewer 为空/`agent:` 前缀/decision≠approve 即 human_acceptance gap）；**安装检查只读**（scope:'installation'——查而不修，与 L00 自检同构）；**三态证据缺一即不完整**（正常、失败、失败后不变——FlowERP 边界 6「越界请求明确判拒，拒绝后原数据不变」的现场需求面承载）。
