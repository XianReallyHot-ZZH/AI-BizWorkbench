# L04 - 受控执行

> 延伸阅读（上游原讲义）：`vendors/CodexFDE/docs/courses/L04/`（README / 辅导资料 / 实践操作手册 / 行动卡 / 交付机制与故障选读 / prompts×4 / `skills/controlled-delivery-handoff/` / `scripts/check_inventory_delivery.py`）。上游标题"委托 Codex 执行一次最小变更"。原讲义口径为 Windows PowerShell + Codex CLI + `course-submit --execute-code` + serve-workbench Web 复核；本讲义为 macOS + Claude Code（ADR-0002）+ 候选分支（ADR-0004）+ 纯 CLI 复核口径。对照基线 `CodexFDE@7f67533`（检查点 0002；本次会话现查 `origin/main` 仍为 `7f67533`，冻结合同无变化，无新检查点）。

## 1. 讲解

L01 让工作台能记账，L02 固化了长期规则，L03 交付了单次合同与结构解析器——但**能读合同不等于能组织一次开发**。本讲补上这最后一环：受控执行。补齐之后工作台达到 **V0**：绑定 Spec、创建任务、限制写集、调用执行器、收回 Diff 与命令结果、运行最小 Eval、停在人工复核前。这是 roadmap 阶段 3，也是**换挡点**（CONTEXT.md「自举」词条）：L01–L03 由人直接监督 AI 建工作台，本讲 A 票仍是这个形态；A 被具名验收后，B 票改为**通过工作台**组织交付——L05 起协同都走这条路径。自举的有趣处在于递归：A 票造的笼子，关的正是造笼子的同一个执行器（Claude Code）。

**唯一顺序：A 建设 → A 独立复验 → B 执行 → B 独立复验。** 两张 Ticket 是两张独立任务单（CASE-WB-L04-001 / -002），执行者不能批准自己（Claude 执行、用户具名验收，铁律 2 的结构天然满足）。上游的五问贯穿全程：任务有没有依据、是开发还是只检查、执行有没有边界、结果能不能回查、能不能正确停下。

**客户真理口径（ADR-0005）**：vendors/flowERP 是终态快照，`flowerp/inventory_export.py` 的 `export_inventory_file`（临时文件 + fsync + os.replace + finally 清理）与 `ImportExportService.export_csv` **已存在**（L03 只读调查，`lesson-03-submission/decisions.md` SJ 表）。所以本讲 B 票是"按 Spec 驱动既有能力交付并独立复验"，**不是从零实现**——行动卡自己的约束就是"已经存在的能力只复验，不重复实现"。B 票的真正产出不是新业务代码，而是一条可复查的因果链：L03 确认版 Spec → 已接受的 V0 → 受控候选内的交付驱动 → 六场景独立复验 → 具名决定。

**本讲交付五样**：① 建设合同 `WB-L04-BOOTSTRAP.md`（六段结构，经 spec 入口解析通过）；② 工作台 V0（REGISTRY 缝第二批命令：受控执行、写集检查、最小 Eval、摘要、人工复核门）；③ 交付证据链（A/B 两任务单、候选绑定、L03 Spec SHA-256、实际写集、Diff、命令与退出码）；④ `lesson-04-submission/` 五文件 + probe 六场景报告（含真实失败实验）；⑤ 换挡完成的事实：B 票确实由 V0 组织，不由人会话直接指挥。
