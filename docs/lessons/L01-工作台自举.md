# L01 - 工作台自举

> 延伸阅读（上游原讲义）：`vendors/CodexFDE/docs/courses/L01/`（辅导资料 / 实践操作手册 / 行动卡 / WORKBENCH_SPEC / prompts 三阶段）。上游标题"以终为始：一次可验证的 AI 交付怎样完成？"。原讲义口径为 Windows + Codex CLI + `course-prepare` 隔离区 + `lesson-01-submission/` 个人学习记录；本讲义为 macOS + Claude Code + 顶层全新实现（ADR-0001）+ `lesson-01` 候选分支（ADR-0004）口径。上游对照基线 `CodexFDE@58f4612`（2026-09-25 现查：`origin/main` 即此提交，快照未过期）。

## 1. 讲解

L01 是第一段有代码增量的讲：在仓库顶层从零建出 **Workbench V0.1**——五个 CLI 子命令（`workbench-init` / `workbench-project-add` / `workbench-task-create` / `workbench-evidence-add` / `workbench-status`），构成任务账 + 命令证据账 + 完整性检查。交付后立即做第一次**自举**：用这个刚建好的工作台登记"个人研发工作台"项目、创建"开发 V0.1"任务，把本讲自己的红灯、Diff、绿灯记录导入进去，让它能查回自身的建设过程。

为什么现在做：L00 只证明了参考实现能诚实运行；从本讲起按 ADR-0001 在顶层全新实现，第一个对象必须是工作台本身——先让它有地方落"任务 → 红/Diff/绿证据"的账，之后每一讲的合同测试证据才有归属地。课程主线在本讲走完整一遍：说清痛点 → 签署需求 → 红灯 → 实现 → 同一测试复验 → 自举。自举也是本复刻"具名验收"的程序镜像：证据链完整后 `acceptance` 仍为 `pending_human_review`，**程序不代签，人才能签**。

与上游学习证据的映射：上游 `lesson-01-submission/` 十余份个人记录 + prompts 三阶段访谈，收敛为本复刻的两样东西——候选分支 commit 历史（commit 1 = 合同测试起始红，commit 2 = 实现后绿，ADR-0004）+ `docs/replication/evidence/L01.md` 工程证据（命令 + 退出码 + 具名验收行）。prompts 三阶段中的"访谈冻结范围""受控实现"由本讲两个用户配合点承担（见 §2/§3），"复验与自举"由 §3.D 与 §4 人审承担。

因果交接：本讲只保证"记录可追溯"。L02 把仓库规则写进 `AGENTS.md`（越界请求被规则判拒）；L03 六段式 Spec 解析器；L04 换挡点——工作台 V0 首次组织 Claude 受控交付 FlowERP。FlowERP 本讲冻结不接入（`flowerp_connected: false` 是**预期值**，不是缺陷）。

### D. 正式复验 + 自举

## 附录 A：Java 重走移植注记（ADR-0006）

> 状态：**计划草案，待用户审定；审定前不动手**。决策与词汇见 ADR-0006 与 CONTEXT.md（重走 / 对照基准 / 移植注记）。§1–§4 为 Python 口径的历史对照基线，不重写；本附录只记录 Java 重走侧的翻译点与增量。重走证据落 `docs/replication/evidence/L01-java.md`（原 `evidence/L01.md` 不重开）。

### A1 讲解

为什么从 L01 重走：信用内核（账本只追加、失败不可抹、SHA-256 复核、链判定三规则、`acceptance` 恒待人签）是后续所有讲的地基，地基必须落在验收人读得懂的语言上（ADR-0006 Why）。重走不是翻译旧代码，而是**用 Java 重新满足原讲合同**：验收项 C1–C11 的行为语义逐条不变，变的只是载体（语言、构建、测试运行器、路径）。Python 版在本讲期间冻结为对照基准，产出 golden 文件供验收门比对；它保留至 L06 重走完成才退役。

因果交接（对 §1 的修正）：L02–L06 重走依次跟随；L07（Hook 护栏）顺延至重走完成后。本讲为重走线建立三块模板件，后续每讲直接复用——候选分支 `lesson-NN-java`、Java 版证据导入工具（复刻 vendor `import_evidence.py` 语义）、golden 生成与比对机制。
