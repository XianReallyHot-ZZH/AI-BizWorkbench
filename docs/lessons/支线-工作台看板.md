## 1. 讲解

### 1.1 本支线要什么

验收人现在看账全靠 sqlite3 命令：链判定、执行记录、记忆状态都是"抽象"的表行。本支线把"看账"升级为**本地只读面板**：起一个 server，浏览器里看到四屏——任务与红绿链（含全局锚定状态）、受控执行与复核记录、记忆资产、工作台身份与完整性判定。MISSION 直接受益：**读懂并验收本工作台**——看板不改任何账，只让账可读。

### 1.2 客户真理现查（讲前 2026-09-28）

上游 `serve-workbench` = "跟跑必做驾驶舱（默认 :8001）"（`workbench/cli.py:51`），背后 `workbench/workbench_server.py`（546 行）：

1. **GET** `/api/health`、`/api/v1/projects`、`/api/v1/initiatives`、`/api/course/*`、`/api/cockpit/upgrade`、`/api/v1/tasks/*`、`/api/v1/delivery/views` 等；
2. **POST** 建项目、建倡议、建任务、交付请求——**上游驾驶舱是可写操作台**；
3. 前端 `workbench_web/`（原生 JS：workspace-dashboard / initiatives / learning）+ `harness_web/` 另一套。

**结论**：上游面板的定位是操作台，正题在 L13/L14。本支线只做**观察窗**——只读是第一合同，零 POST、零操作页。上游 JS 资产留作 L14 对照，本支线不搬。

### 1.3 与既有裁决的边界

- **L04 D6「serve-workbench 不建」**：当时是主线非目标（L04 只建受控执行）。本支线**显式重开**，但取最小形态且换名（`workbench-dashboard`），避免与上游命令撞名的歧义。
- **L13 Task API**：本看板**直接只读 sqlite 账本**，不建 REST API、不承诺接口合同。若 L13 落地 API，看板可迁移为 API 视图——演进路径如实记录，不预设。
- **L14 面板/ERP 操作页**：正题。本支线产物届时作为对照起点之一，不是它的替代。

### 1.4 因果交接

L06 起质量链会产出更多账面状态（eval 分级、判决、退出码），看板是验收人的常态工具；四屏里的"红绿链 + 锚定状态"一屏化后，0006 课的辨别力三问有了肉眼入口。

## 2. 本支线合同（C 编号清单，自拟）

| C | 验收项 | 类型 | 怎么验 |
|---|---|---|---|
| C1 | 只读性 | blocking | sqlite 以 `mode=ro` URI 打开；路由仅 GET（POST/PUT/DELETE → 405）；起停一次服务前后账本文件 sha256 不变 |
| C2 | 数据保真 | blocking | fixture 种子账（建项目/任务/红绿链/执行记录）后，面板渲染的任务数、相位、`acceptance: pending_human_review`、`evidence_complete` 与 sqlite 直查逐一一致 |
| C3 | 错误面 | blocking | runtime-dir 不存在 / 非本工作台账本 → JSON 错误契约（词面对齐 `required_task_missing` 族）；账本缺表（老版本）→ 该屏降级为空，不裸崩 |
| C4 | 四屏覆盖 | blocking | 任务与证据链（相位 + 锚定）／执行与复核记录／记忆资产（S01 五表在主账有真数据）／身份与 status 判定，四屏各有种子断言 |
| C5 | 零依赖 | blocking | 仅标准库（imports 白名单断言进合同测试）；本仓库铁律 |
| C6 | 绑定安全 | blocking | 默认绑 `127.0.0.1`，`--port` 显式；默认配置无对外暴露面 |
