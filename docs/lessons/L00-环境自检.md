# L00 - 环境自检

> 延伸阅读（上游原讲义）：`vendors/CodexFDE/docs/courses/L00/`。原讲义口径为 Windows + Codex CLI + 课程命令链；本讲义为 macOS + Claude Code + 候选分支口径（ADR-0002/0004）。

## 1. 讲解

L00 不产生任何工作台代码。它只做一件事：**证明这台机器能诚实运行参考实现**。

为什么这是第 0 步：本复刻的每一讲都要"对照复刻"——我们的合同测试要和参考实现的测试互为参照，客户真理要跑 flowERP 自己的 eval。如果环境不能先把参考实现跑绿，后面所有的"红转绿"都无法区分"我实现了"和"环境本来就不行"。课程原话同样强调：不得把 `serve`/`demo`/`course-status` 的存在当作通过证据——**证据 = 命令 + 退出码**。

本讲还有一个一次性的平台决策落地：参考仓库是 Windows-first（`.cmd`、`-X utf8`、PowerShell），macOS 口径从本讲起补齐（B3 决策）。已知偏离：课堂统一 Python 3.11，本机用系统 3.13 建 `.venv`（pyproject 只要求 ≥3.10，偏离记录在证据里即可，不构成失败）。

## 3. 实操流程 + Claude 简报

L00 无代码增量，**不走候选分支**（ADR-0004 例外条款）：在 master 上执行，证据直接落 `docs/replication/evidence/L00.md`。

命令清单（macOS，逐条执行并记录退出码）：

```bash
# C1 + C2：工作台侧
cd vendors/CodexFDE
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/flowerp-workbench eval.harness --suite blocking        # 期望 10/10 通过、退出 0

# C3：客户侧（客户自己的 .venv，自己的入口）
cd ../flowERP
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -X utf8 -m eval.harness --suite blocking        # 期望 19 项通过、退出 0

# C4 + C5 + C6：环境自检（回到工作台侧）
cd ../CodexFDE
.venv/bin/flowerp-workbench environment-check                     # 期望 ok: true
.venv/bin/flowerp-workbench environment-check --product --product-root ../flowERP   # 期望 ok: true
.venv/bin/flowerp-workbench course-status                         # 记录 contract_valid / course_ready 现状

# C7：版本台账
python3 --version && git --version && claude --version && codex --version
```

命令参数如有出入，以 `<命令> --help` 实际输出为准并在证据中注明。
