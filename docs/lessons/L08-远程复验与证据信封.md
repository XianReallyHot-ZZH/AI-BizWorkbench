## 1. 讲解

### 1.1 本讲要什么

L07 交出的统一 Harness + Stop 护栏回答的是**本地什么时候检查**。L08 的问题是**别人凭什么信**：你电脑上的绿报告，审核者需要在可追查的另一套环境里取明确版本、运行同一组检查、保存结果——这就是 CI 的价值所在（可追查，不是"远程天然更可信"）。同一 Eval 身份 = 本地与 CI 调**同一个统一入口、同一组登记项**；环境准备可以不同，业务标准不能偷偷变成两套。本讲主实验 A/B/C 拆开两个命题：**A 假绿**（业务缺陷在场、检查发现失败、工作流却吞掉退出码显示绿——证明"绿色"可能来自错误流程）→ **B 可信红**（只修失败传播，业务缺陷不动——证明检查流程诚实）→ **C 可信绿**（只修业务，流程不动——证明业务在同一标准下恢复正确）。每次只改一个层，结果变化才可归因。B 的红灯就是第一次修复的目标。

### 1.2 业务案例：整单原子预占（正式 SalesService 面）

订单两行：A 商品 2 件、B 商品 3 件，B 只有 2 件。整单语义：所有行都能满足才一起留货；任一行不足，本次预占**全部不生效**。坏实现先为 A 预占再发现 B 不足报错——页面显示失败，A 的可用量却从 5 降到 3，其他订单少了两件可用货。观察面是**四张表**（stock_balance / stock_reservations / sales_document_lines / sales_documents），不能只看错误消息或订单状态。两个关键教学点：①正式销售入口**先 confirm 再 reserve**，预占失败后订单保持 confirmed 是**正确**状态（不能误要求退回草稿——L07 草稿门面是另一个入口，状态名不可互搬）；②**普通缺货不足以证明原子性**——正确实现在写入前规划期就拒绝缺货，中途写入失败（第二行 INSERT 时故障）能否整体回滚才是原子性区分器，所以实验必须有 write-error 模式（临时库装触发器让第二条预占记录插入失败）。

### 1.3 客户真理现查（讲前 2026-09-30，`vendors/flowERP` submodule 只读）

1. **原子预占面在场且事务语义完备**：`flowerp/sales.py:279` `SalesService.reserve`——docstring「Reserve every remaining line in one transaction; any shortage rolls all back」；规划期全行 FEFO 分配 + 缺货即抛（写入前），写入段逐行 UPDATE（带 `on_hand-reserved>=?` 条件）+ INSERT 预占记录；`flowerp/store.py:125` `ERPStore.connect` yield→commit / Exception→rollback+raise。**客户实现已正确，本讲业务面是检查与 CI，不是重写**；
2. **绑定 eval 两件在场**（blocking）：`stock_never_negative`（`eval/harness.py:26`）、`sales_credit_and_atomic_reservation`（`eval/harness.py:38`；`eval/cases.py:277`——单行缺货，断言 `reserved==0 and available==2`）。关键事实：单行缺货对 `conn.commit()` 注入缺陷**不可见**（缺货在规划期拒绝，尚未写入）——多行 + 中途写入故障覆盖是本讲新增裁判（上游 README 明示「默认检查是一行缺货，不能替代」）；
3. **教学缺陷权威形态**（上游 `assets/latest/injected-atomic-defect.diff`，逐字）：`sales.py` 逐行写入循环内 `UPDATE sales_document_lines …` 行后插一行 `conn.commit()  # L08 teaching defect: commit each line too early`——每行提前提交，write-error 中途故障后回滚只回滚未提交部分，第一行残留即部分预占。锚点行在文件内唯一（L05/L06/L07 锚点唯一性校验同款）。暴露面唯一：`l08_atomic_reservation_write_error` 在缺陷树红（before≠after），shortage/pass 两模式在 correct 与缺陷树下都绿——红点唯一，受控对照干净；
4. **第三绑定 eval `ci_evidence_envelope_is_honest` 不在客户**（上游同——学生在自己仓库登记；Java 线 = 本讲新登记项，六边界机检）；
5. **CI 可行性**：flowERP `dependencies = []` 纯标准库，`setup-python` 3.12 直接跑无需装包；本仓库 `mvn test` 唯一 python 依赖点 = `EvalHarnessContractTest:202` 用 `basedir/.venv/bin/python` 跑客户 harness——CI 加一步 `python -m venv .venv` 即本地同形；探针解释器经 `--python` 显式传**绝对路径**（`resolveInterpreter` 只做 cwd 绝对化不查 PATH）。

**结论**：本讲增量如实转为——①**原子预占检查面**（上游 `atomic_reservation_lab.py` 三模式的 Java 对应物：探针驱动客户实现 + 四表断言留 Java）挂进统一入口；②**证据信封件**（上游 `workbench/ci_evidence.py` 的 Java 对应物 + REGISTRY 命令）；③**CI 工作流与 A/B/C 真实 Run 链**（GitHub Actions，同一工作流三态三次真实运行）。
