## 1. 使命定位

**为什么现在做**：工作台三件套 = Harness + 记忆系统 + 工作流蒸馏（CONTEXT.md「工作台」词条）。L04 收口后 Harness 骨架已立（任务账、证据账、受控执行三命令、flowERP 首驱），记忆系统是三件套中尚未动工的第二件。roadmap 定位：支线在 L04 后、L05 前串行插入。

**完成标志**（roadmap 逐字）：召回→采用→复验→失效证据链走通一次。

**上游口径（逐字，调查笔记 §5）**——闭环判定的权威定义（`vendors/CodexFDE/AGENTS.md:49`）：

> 单次交付成功、事件持久化、反馈登记或资产登记，均不足以证明三者已闭环。完成须有跨事项证据：前一事项经验被后一事项召回，流程版本被明确采用，Harness 执行并保留 Eval 与人审结果，复用失败可追溯并触发修订或停用。

**与上游的诚实差距**：上游记忆系统已有首版实现（learning.py 552 行 + feedback/evolution 两级前置账），但上游自己记录：`tests/` 中 LearningStore 专项测试**零命中**，回归 `30 tests, errors=10`，"六步已有首版代码对应，但尚未形成通过验收的完整交付"（调查笔记 §5、§8.6）。本支线以合同测试先行（正常+失败路径）超过上游测试口径；对上游未完成部分（专项测试、效果统计）如实标"待建设"，不冒充对齐。

## 2. 范围：最小闭环裁剪

**做**（memory 类资产全链）：

来源准入（仅"已验收任务"入口）→ 候选 create → 具名审核 approve/publish → 召回（关键词 applies/excludes + 项目隔离 + 字符预算 + 冲突显式分组 + 召回包整体落库）→ 逐项采用决定 → 采用快照 BIND 封存 → 复验链逐相位执行 → 结果回写 outcome → 失效治理（撤回 revoke / 被替代 superseded，不删除）。

**不做**（标"待建设"，与上游口径一致，见 §6 D2）：

- feedback / evolution 两级前置账（上游"已接受失败反馈"来源入口的级联机制）
- workflow 类资产：流程候选、试用（trial_approved）、复用失败自动停用
- HTTP/前端事项工作区（上游的记忆治理入口）——本支线治理入口走 REGISTRY CLI

**范围收敛的后果（如实声明）**：workflow 类推迟期间，上游 AGENTS.md 全口径闭环判定（含"流程版本被明确采用"）无法完整声称；本支线完成只声称 roadmap 口径（召回→采用→复验→失效链走通）。

## 3. 六步各自的证据形态

上游自己的"最小可交付闭环"六步（`docs/architecture/工作台范式与闭环建设.md:79-88`）与本仓库落点的映射。上游措辞是**提炼→具名审核→召回/决定→流程候选→采用执行→回写治理**（调查笔记 §6）；roadmap 完成标志的四链时刻落在第 3/5/6 步内，两者不冲突。

| 步 | 上游机制（引用见调查笔记 §2） | 本支线复刻形态 | 证据形态（落库） |
|---|---|---|---|
| 1 提炼候选 | `create`：来源只收已验收任务或已接受失败反馈；来源快照整体嵌入 payload 附 sha256 | 只做"已验收任务"入口（`status=completed` + 具名 approve 复核）；从 L04 已验收任务提炼真实经验 | `learning_assets` 行（state=candidate）+ `learning_events`（action=candidate）+ source 快照 sha256 |
| 2 具名审核 | `govern`：approve/publish/revoke；必须非提炼者独立审核；`human()` 拒绝 AI 名义操作人 | 用户具名审核；同一 `human()` 门槛 | `learning_events`（approve/publish）+ state 迁移 candidate→active |
| 3 召回+决定 | `recall`：项目+状态过滤、关键词命中/排除、同源事项不得自用、字符预算、conflict_key 冲突显式分组、检索不到如实为空；包整体落库 RECALL-*；`decide` 逐项 adopt 布尔+理由+操作人 | CLI 召回命令（REGISTRY 缝）；决定逐项记录 | `learning_recalls` 整包行；决定固化进绑定 payload |
| 4 流程候选 | workflow 提炼+绑定版本+隔离复验+显式试用 | **待建设**（本支线不做，见 §2） | — |
| 5 采用执行 | `bind`：采用资产全文快照+参数+前置检查封 BIND-* 附 sha256，一次交付一条；`validate_binding` 执行前后两次防漂移；采用的有界结论注入冻结 Spec；执行链逐相位 precheck/implement/eval | bind 命令 + 执行前复验 + 三相位落库 | `learning_bindings` 行（UNIQUE plan/task）+ `learning_runs`（precheck/implement/eval） |
| 6 回写治理 | `finish`：review+outcome 相位，通过须具名验收；失败保留轨迹；workflow 复用失败自动停用；发新版原子置旧版 superseded | outcome 回写（passed 须具名验收，对齐"待审核 ≠ 已接受"）；v2 发布 → v1 原子 superseded；revoke 通道 | `learning_runs`（review/outcome）+ `learning_events`（superseded/revoke，带 replacement） |

**相位裁决的场内事实**：上游两套相位互不混用——L01 四相位 `red/diff/green/observation` 只服务任务证据账；记忆复用链自有五相位 `precheck/implement/eval/review/outcome`（`workbench/learning.py:195-198`），`UNIQUE(binding_id,phase)` 每相位只记一次。记忆链的"链"是 **sha256 快照链**（内容、来源、报告、快照读取/执行前重算复核），不是红绿链（调查笔记 §3）。

## 4. 实施机制

- **候选分支同款**（ADR-0004 纪律全适用，支线非编号讲次）：分支名候选 `side-memory`；commit 1 = 合同测试（起始红）+ 红证据；commit 2 = 实现 + 与红同一测试命令的 Diff + 后绿（observed_at 严格递增）。
- **模块落点**：新模块 `workbench/learning.py` 经 REGISTRY 缝注册（`cli.py:18`，L03 spec / L04 execution 同形第三批）；存储复用单一 sqlite 账本新增 `learning_*` 五表（沿 L04 先例：单一 DDL 来源，init 与旧账迁移 `_ensure_v0_schema` 共用）。
- **相位实现**：新模块自有五相位常量，`bootstrap.PHASES` 四相位冻结**不动**（不碰信用内核）。
- **工作台自驱**（换挡点口径）：支线工作登记进任务账，实现/复查走受控执行与执行记录；闭环走通的目标任务也用真实 task_id（见 §6 D6）。
- **执行期技能编排**：`codebase-design`（schema/召回接口设计，模型自调）→ `tdd`（红绿循环，模型自调）→ 遇障 `diagnosing-bugs`（模型自调）→ 收口前 `code-review` 双轴（模型自调）；`/mattpocock-skills:implement`（用户显式，执行期到点提醒）；若用户要第 2 段合同形态，`/mattpocock-skills:to-spec`（用户显式，本方案 §3 表可作其输入）。

## 5. 验收门与人审清单（第 4 段形状）

**合同测试种子**（正常 + 失败路径；正式 C 编号在动手时随起始红落定）。从上游规格验收场景清单（`docs/architecture/工作台范式与闭环建设.md:90-98`，调查笔记 §8.8）映射：

1. 跨项目召回/采用/治理被拒（项目隔离）
2. 撤回/被替代的记忆不默认注入召回
3. 跳过审批被拒（未 publish 不得召回；outcome passed 必须有具名验收，否则报"复用验证缺少具名验收"）
4. 复用失败不得因历史成功标记通过（outcome 独立判定）
5. 重启后引用链可恢复（每次读取重算 sha256 复核）
6. 新版本不改写旧快照（superseded 保留 v1 快照与全部历史事件）
7. 检索不到如实为空（不编造召回）
8. `human()` 拒绝 AI/待定名义操作人
9. 非法状态迁移拒绝（如已 revoked 再 revoke）
10. 内容漂移阻断（payload 被改 → 校验失败报错，不静默）
11. 一次交付最多绑定一条（plan/task UNIQUE）
12. 同源事项不得作为独立复用

**验收门**：全量合同测试绿 + 证据账 `docs/replication/evidence/S01.md`（C 编号逐项结论 + 命令台账 + 失败现场 + 末尾具名验收行）+ `code-review` 双轴复查（发现按 test-first 修复并保留旧证据）+ 用户按本节清单具名验收后 `git merge --no-ff side-memory`。

**人审清单**：看候选分支两个 commit 的 diff（先测试后实现）；亲手跑红绿同一命令核对 observed_at 顺序；抽查失效路径（撤回后召回确实不注入、历史事件还在）；核对证据账与任务账/执行记录互证；红旗 = 合同测试先写实现后补、sha256 复核被跳过、失败记录被删。

**D7 词条提案**（候选措辞，经确认后入 CONTEXT.md）：

> **记忆系统 (Memory system)**:
> 工作台三件套之一：把已验收任务的经验提炼为带证据引用的条目，经具名审核后按项目召回、逐项采用并复验，失效不删除只状态迁移。条目四状态 candidate/active/superseded/revoked；内容与采用快照只追加，状态变更不改写历史快照；检索不到如实为空。
> _Avoid_: 记忆库（泛称）、知识库

配套微词条（同批入表）：**记忆条目 (Memory asset)**——带来源证据引用与适用边界的可复用经验（memory 类）或流程（workflow 类，待建设）；**采用快照 (Adoption binding)**——一次交付对某版本记忆全文的封存引用（BIND），执行前后复验防漂移。
