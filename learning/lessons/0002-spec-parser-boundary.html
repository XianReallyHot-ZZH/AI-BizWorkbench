意图：一句话怎么变成合同，闸门为什么存在

L03 的起点是客户的一句话："给我导出一份库存，我要知道还有多少货能卖。"这句话没法开工——列、行粒度、空库存、失败行为全是未知数。本讲把它做了三层转化：

模糊需求
   ↓ 回答八个业务问题（谁用 / 一行是什么 / 公式 / 列 / 排序 / 空结果 / 失败 / 不变量）
决定记录 decisions.md
   ↓ 起草 V1 → 反例审查抓歧义 → 逐条裁决
可验收合同 FDE_SPEC.md（六段确认版）
   ↓ 建设读取工具 + 用三份输入证明它的边界
工作台结构闸门（workbench.spec）

分层纪律是全讲的魂，一句话版本：解析器只回答"六段结构是否完整"，绝不冒充业务裁判。结构通过 ≠ 业务正确；把公式写错的合同照样通过解析，退回它的是人。这条边界在 L04 尤其要紧——执行器见到"解析通过"只能得出"合同可读"，永远不能得出"需求正确"。

为什么这值得做成闸门没有它，残缺需求会流进执行，事故在业务现场才暴露；有了它，缺章节的合同在 workbench.cli spec 一步就被拒，错误词面直接指认缺哪一节——修复成本从"执行后返工"降到"进门前退回"。

机制：六类拒绝与一个屏蔽器

解析器公开接口只有三个（vendor 冻结同形）：parse_spec(text)、load_spec(path)、ParsedSpec.as_dict()。成功返回六字段对象：source / goal / non_goals / constraints / acceptance / done——中文标题映射为程序字段，后续程序按字段读取，不用重新猜标题含义。失败时，六类错误各有可指导修订的词面：

错误类别实际错误词面指导什么修订
缺章Spec 缺少必要章节：非目标补哪一节
空章Spec 章节内容不能为空：目标哪节只剩标题
重复Spec 包含重复章节：目标不许悄悄选一份
乱序Spec 章节顺序错误；应为：…；实际为：…调到应有序
未知标题Spec 包含未知章节：附录删掉或并入正段
围栏未闭合Spec 代码围栏未闭合，请补齐示例的结束标记补结束标记

第六类牵出最精的机制——代码围栏屏蔽。验收用例里常要放 Markdown 示例，示例自己也写着 ## 目标。它位于围栏内，是正文，不是第二个正式章节：读取时必须认出围栏的开始与结束，只在围栏外识别章节，提取正文时仍保留示例原文；围栏没闭合就直接报错，不能把后面的正式章节全吞进示例。这条口径来自上游检查点 0002 新增的教学节（辅导资料·从一段文本看懂解析器怎样工作），并已写进本仓库实现。

代码走读：屏蔽算法的十几行

心脏在 workbench/spec.py 的 _contract_headings()（L33 起）。逐行读懂它，围栏语义就再不会含糊：

for line in text.splitlines(keepends=True):        # 逐行，保留换行
    match = re.match(r"^[ ]{0,3}(`{3,}|~{3,})", line)
    if fence:                                      # 已在围栏内
        if 匹配同字符且更长且无尾注: fence = None    # ← 围栏在此结束
        masked.append(本行非换行字符全部替换为空格)  # ← 屏蔽，但保留换行
    elif 匹配围栏开始且行内无反引号:                # 围栏开始（```markdown 等）
        fence = (字符, 长度)                        # 记住用哪种围栏、多长
        masked.append(空白化)
    else:
        masked.append(line)                        # 围栏外，原样保留
if fence: raise ValueError("Spec 代码围栏未闭合…")  # 走到文件尾还开着 → 拒绝

三个容易忽略的设计点：

① 屏蔽是替换成空格，不是删除——保留字符偏移量，后面才能用 match.start()/end() 在原文上精确切分正文（docstring 说的 "preserving original text offsets"）。② 闭合要求同字符且不少于开始长度——用 ``` 开的不能拿 ~ 收。③ 屏蔽之后，parse_spec() 对屏蔽文本做 ^## 标题 的多行匹配——围栏内的 ## 在物理上已被抹平，结构上不可能被误认。

随后 parse_spec() 按固定顺序检查：未知 → 重复 → 缺章 → 乱序 → 空章。顺序不是装饰——L03 的合同测试夹具就因此暴露过一个真 bug：构造"空目标"的字符串替换意外多造了一个「非目标」节，重复检查先触发，报的是"重复章节"而非目标词面（证据账 §3 夹具修正现场）。顺序错一个，错误提示就指错方向。
